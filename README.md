# dsh-plugin-learn

English | [中文](README.zh.md)

A [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) plugin for learning algorithms with LeetCode-style practice. It works in **DSH Desktop** and **DSH Web**.

- **Lessons**: 16 topics, from hashing, two pointers, sliding window, binary search, and stacks to linked lists, matrices, graphs, backtracking, heaps, greedy algorithms, data structure design, and dynamic programming. Each lesson has a motivation, a strategy, a worked example with a step-by-step trace, an understanding check, a practice problem, and a reflection.
- **Practice**: 108 real LeetCode problems, including all of **LeetCode Hot 100** (Top 100 Liked), with original summaries and links to the official statements. Statements are not copied. The **Hot 100** view follows LeetCode's own grouping and shows your progress per group. Each problem has an editor, Run and Submit, custom inputs, notes, and attempt history. Design problems (LRU Cache, Min Stack, …), in-place problems, and node-reference problems (linked-list cycles, intersections, random pointers, lowest common ancestor) are judged like on LeetCode.
- **Add problems**: describe what you want to practice in your own words ("3 medium BFS problems I have not done"). An AI agent searches LeetCode's public problem list, writes an original summary, hints, a reference solution, and an independent brute-force checker, and adds each problem only after it passes the same validation as the built-in problems. No JSON needed.
- **Judging**: your code runs in a Docker container with no network, a read-only filesystem, and memory, CPU, and process limits. The verdict comes only from the tests. An optional AI judge adds feedback but cannot change the verdict. A pass means "passed local tests", not LeetCode acceptance.
- **Tutor**: hints unlock one level at a time (direction, key observation, outline, solution), and the solution level asks for confirmation. Tutor chat streams replies and does not hand out full solutions unless you ask for them.
- **Reviews**: spaced repetition on a 1/3/7/14/30-day ladder in your timezone, with a daily limit. Each review uses a validated variant of the problem rather than repeating it. New variants are generated by AI and must pass automated validation before use.
- **Reminder email**: off by default. It needs a verified address and opt-in. By default messages are only written as previews; real SMTP sending requires explicit configuration.

Explanations are in Chinese by default; switch to English in Learn → Settings.

## Requirements

- **DSH 0.2.0-rc.2 or newer, below 0.3.** DSH refuses to load the plugin on other versions.
- **Docker** running on the same machine, with the runner images pulled once:

  ```sh
  docker pull python:3.13-alpine node:24-alpine
  ```

  You can also use Learn → Settings → Prepare runner. Without Docker, Learn shows evaluation as unavailable; it never runs your code directly on your computer.
- **Optional:** a default model configured in DSH (for example, signed in to DeepSeek) for the tutor, AI judge feedback, reflection feedback, and new variants. Without a model, Run, Submit, verdicts, and the written hints still work.

## Install on DSH Desktop

1. Open **Plugins** in Desktop and install from the GitHub source `github:kapelame/dsh-plugin-learn`.
   To use the command line instead, quit Desktop completely, then run Desktop's bundled CLI:

   ```sh
   "/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add github:kapelame/dsh-plugin-learn
   ```

2. Reopen Desktop and choose **Learn** in the sidebar.

## Install on DSH Web

```sh
dsh plugin --profile web add github:kapelame/dsh-plugin-learn
dsh web
```

Use the profile name your Web setup boots (`web` is the default Web profile). Then open **Learn** in the sidebar.

The repository ships prebuilt files in `lib/`, so installing from GitHub runs no build script and needs no extra build permission. Pin a commit for reproducible installs: `github:kapelame/dsh-plugin-learn#<commit>`.

## Configuration

The plugin adds two rows to your profile: `learn` (the service, `dsh-plugin-learn/service`) and `learn-ui` (the Remote API and the browser UI, `dsh-plugin-learn`). Override settings in the profile's `cordis.patch.yml`. For example:

```yaml
- id: learn
  config:
    dataRoot: !!js dshHomePath('learn')
    defaultLocale: en
    reviewDailyLimit: 3
    agents:
      judge: false              # deterministic judging only, no AI feedback
      variantGeneration: true
    email:
      transport: capture        # 'smtp' sends only with liveSendingAuthorized: true
```

A patch replaces the row's whole `config`, so keep `dataRoot` in it. Learn data lives in `learn/` under your DSH home (`~/.dsh` by default). Settings can export it as JSON or reset it.

Real email needs `email.transport: smtp`, `email.liveSendingAuthorized: true`, `email.smtp.host`/`port`/`user`, and the SMTP password stored as the DSH credential named by `email.smtp.passwordRef` (default `DSH_LEARN_SMTP_PASSWORD`). Without implicit TLS, STARTTLS is required.

## Add problems (problem finder)

Practice → **Add problems** opens a dialog with a free-text description and a count (1–5). The run shows its progress live (searches, inspected problems, validation attempts, added or skipped problems) and can be stopped at any time; problems already added stay.

- The agent follows the bundled skill [`skills/learn-problem-author/SKILL.md`](skills/learn-problem-author/SKILL.md). It is registered only inside the finder agent, so it never appears in your normal Sessions.
- Problem number, title, difficulty, tags, the judged signature, and the example inputs always come from LeetCode's metadata, never from the model. Paid-only problems and problems that need a judge Learn does not provide are skipped.
- Every submission runs the reference against the brute-force checker on generated inputs, checks boundary cases, and freezes a test suite. Failing submissions are rejected with the failing checks, and the agent gets a limited number of retries per problem.
- It needs a default model and Docker. Settings live under `finder` in the `learn` row:

```yaml
    finder:
      enabled: true
      maxProblems: 5                 # problems per run
      maxSubmissionsPerProblem: 3
      maxLeetcodeRequests: 40        # LeetCode requests per run
      requestIntervalMs: 1000        # pacing between LeetCode requests
      leetcodeEndpoint: https://leetcode.com/graphql
      leetcodeCnEndpoint: https://leetcode.cn/graphql/   # Chinese titles; '' disables
```

## Privacy and model use

- Code runs only inside Docker containers without network access. Expected answers for hidden tests never enter the container.
- When a default model is configured, these actions send the problem summary and your current code to that model through DSH: Submit (unless `agents.judge: false`), hints, tutor chat, reflections, and variant generation. Add problems sends your description and LeetCode metadata (never your code). Each run is an ordinary DSH Session and appears in your Session history.
- Add problems queries LeetCode's public GraphQL API (leetcode.com, and leetcode.cn for Chinese titles) for problem metadata only: no login, no statements, paced requests with a per-run budget.
- No data leaves your machine otherwise, except reminder email when you configure SMTP.

## Limitations

- Docker is required for running code.
- Reminders are sent only while DSH is running with the plugin enabled. A missed daily digest is sent later the same day, never on a later day.
- TypeScript submissions have their types removed but are not type-checked.
- The tutor sees only the last ten messages of a conversation.
- While an AI run is active, its Session briefly appears in the sidebar.
- On Desktop, links in reminder emails point to Desktop's local server, whose port changes on each launch. Use the verification code shown in the email instead, or set `email.publicBaseUrl`.

## Build from source

The sources in `source/` are three DSH workspace packages. They build with the DSH toolchain, so a DSH checkout is required:

```sh
git clone https://github.com/deepseek-ai/deepseek-harness.git dsh
git -C dsh checkout dsh-v0.2.0-rc.2
node scripts/build.mjs ./dsh          # copies the sources in, runs pnpm install and the DSH build, then assembles lib/
```

Use `--skip-install` to rebuild an already-installed checkout. Tests run inside the checkout: `npx vitest run packages/experimental/learn/tests` (needs Docker and the runner images).

Course content lives in `content/` (`content/collections/hot-100.yaml` lists the Hot 100 groups): each problem has YAML metadata with declarative input domains, a reference solution, an independent brute-force oracle, optional hooks, and a frozen test suite built and validated by the generator (reference/oracle differential testing, mutant detection, boundary coverage). `authoring/` holds the scripts that generate the Hot 100 content (`build_content.py`) and freeze its suites (`freeze.sh <dsh-checkout>`).
